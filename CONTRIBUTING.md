# Contributing to DyraSQL

Obrigado pelo interesse em contribuir com o projeto DyraSQL!

## Estrutura do Repositório

Este é um repositório de Trabalho de Conclusão de Curso (TCC). A estrutura está organizada da seguinte forma:

- **`src/`** - Código-fonte do framework DyraSQL (aceita contribuições)
- **`latex/`** - Monografia acadêmica (documento finalizado, apenas correções pontuais)
- **`docs/`** - Documentação Sphinx + PDFs de entrega
- **`references/`** - Referências bibliográficas
- **`data/`** e **`results/`** - Dados e resultados dos experimentos
- **`tools/`** - Scripts auxiliares

## Como Contribuir

### 1. Software (`src/`)

Contribuições para o código do DyraSQL são bem-vindas! Você pode:

- Reportar bugs via Issues
- Propor melhorias na lógica de roteamento
- Adicionar novos algoritmos de decisão
- Melhorar a documentação do código
- Otimizar performance

**Fluxo de contribuição:**

1. Fork este repositório
2. Crie uma branch a partir de `developer`: `git checkout -b feature/sua-feature`
3. Faça suas alterações
4. Teste localmente
5. Commit com mensagens claras (use conventional commits)
6. Abra um Pull Request para `developer`

### 2. Documentação Técnica (`docs/`)

Contribuições para documentação técnica são aceitas:

- Correções de erros
- Melhorias na clareza
- Tradução de documentos
- Exemplos adicionais

### 3. Monografia (`latex/`)

A monografia é um documento acadêmico finalizado. Apenas correções pontuais (erros de digitação, referências quebradas) serão aceitas via Issues.

## Processo de Revisão

1. Todas as contribuições passam por revisão
2. Pull Requests devem ter descrição clara do que foi alterado
3. Código deve seguir o estilo existente no projeto
4. Testes devem passar (quando aplicável)

## Branches

- **`main`** - Branch estável, apenas para releases finais
- **`developer`** - Branch de desenvolvimento ativa (use esta para PRs)

## Issues

Ao abrir uma Issue:

- Use um título descritivo
- Descreva o problema ou sugestão claramente
- Inclua logs ou screenshots quando relevante
- Identifique se é bug, feature request, ou questão

## Código de Conduta

- Seja respeitoso e construtivo
- Foco em melhorar o projeto
- Discussões técnicas são bem-vindas
